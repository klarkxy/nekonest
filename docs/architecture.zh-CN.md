# 架构

本文只说明稳定的组件与所有权边界。包级细节和线上字段属于源码与协议 schema。

## 系统形态

<div align="center">
  <img src="./images/how-it-works.zh-CN.jpg" width="920" alt="手机连接 VPS，Windows 或 Linux 主机上的 Daemon 主动出站连接并控制本地编码智能体">
</div>

| 组件 | 职责 | 不拥有 |
|---|---|---|
| 手机 PWA | 鉴权界面、配对、会话视图、提示词、附件和按能力开放的控制 | 原生会话或智能体凭据 |
| VPS Server | 鉴权、转发、必要持久化、附件与可选 Web Push | 原生智能体历史或主机文件系统访问 |
| 主机 Daemon | 主动出站连接、原生发现/历史、投递日志和智能体进程控制 | 产品账号或公网入口 |
| 原生智能体 | 线程存储与实际编码智能体执行 | 手机/VPS 传输 |

Daemon 始终主动出站连接。PWA 与 Daemon 不跨家庭网络直接连接。

## 数据所有权

- 原生智能体存储是线程发现、历史和所有权的事实来源。
- 手机呈现派生的**目录 → 智能体 → 线程**树，不改写原生会话数据。
- Server 只持久化鉴权、转发、可靠投递、附件和通知所需状态。
- sealed 传输让应用正文在手机与 Daemon 之间保持加密；open 传输允许 Server
  读取明文。

## 交互流程

```text
手机操作
  → 已鉴权的 Server 转发
  → Daemon 校验与可靠投递边界
  → 所选原生智能体
  → 结果沿原路径流式返回
```

网络写入不等于智能体已接受。NekoNest 在重连前后保持稳定消息身份；无法安全
判断工作是否已越过原生智能体边界时，会失败关闭。

新建线程遵守同一规则：手机先创建本地草稿，首条提示词调用受支持的原生启动器，
只有确认原生所有权后，界面才进入真实线程。

## 能力边界

Daemon 是能力生产者，Server 只转发目录，PWA 据此门控每项操作。兼容适配器
不得伪装已安装原生路径没有确认的审批、转向、结构化输入、队列、文件或新建线程
能力。

面向用户的政策见[智能体支持](./agent-capability-matrix.zh-CN.md)。

## 可靠性与安全规则

- 每条 WebSocket 连接一个读取者和一个串行写入者。
- 慢文件系统、智能体或网络操作不持有共享注册表锁。
- 重连代次防止旧连接覆盖新状态。
- 提示词重试复用同一身份；不确定的原生执行不会被静默重放。
- 远端和智能体内容都不可信；PWA 会净化 Markdown。
- 中断、适配器关闭或 Daemon 退出时必须停止主机子进程。
