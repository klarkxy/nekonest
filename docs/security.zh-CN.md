# 安全

NekoNest 是面向单一运维者的自托管桥接器。手机可以向已经以主机用户权限运行的
编码智能体发送工作，因此应把 PWA 访问权视为对这些智能体及其可访问文件的访问权。

## 信任路径

```text
手机 PWA  ⇄  HTTPS/WSS  ⇄  VPS Server  ⇄  主动出站的 Daemon  ⇄  本地智能体 CLI
```

- 主机 Daemon 主动建立连接，家庭网络无需开放入站端口。
- Server 鉴权手机和主机、转发流量并保存必要状态。
- 原生智能体存储和凭据留在主机上。
- 公网环境无论使用哪种传输模式都必须启用 TLS。

## 传输模式

| 模式 | VPS 能读到什么 |
|---|---|
| `sealed` | 路由元数据与加密后的应用正文。提示词、响应、审批、路径、标题和附件正文在手机与 Daemon 之间加密。 |
| `open` | Server 保存或转发的应用正文对 VPS 运维者是明文。 |

新数据目录默认使用 `sealed`。一个数据目录只有一种持久化模式；以后修改环境
变量不会转换模式。只有在明确接受 VPS 可读取应用内容时才使用 `open`。

sealed 模式减少 VPS 暴露，但不会隐藏连接时间、大小、设备/会话路由标识或服务
可用性，也不能防护已经失陷的手机或主机。

## 凭据

| 凭据 | 范围 | 处理方式 |
|---|---|---|
| 管理员密钥 | 初始管理与手机初始化 | 使用长随机值，与其他密钥不同；可用时优先放入私有密钥文件。 |
| 注册令牌 | 新主机注册 | 不要放到手机；怀疑泄露后立即轮换。 |
| 手机令牌与密钥 | 一个手机身份及其已配对主机 | 手机丢失后撤销该身份，并配对新身份。 |
| Daemon 令牌与身份 | 一台已注册主机 | 保护 `~/.nekonest`；失陷后撤销并重新注册。 |
| 智能体凭据 | 主机上的原生 CLI 访问 | 不要复制到 VPS 或 NekoNest 配置。 |

不要把凭据、私钥、数据库、附件、原生转录或 Daemon 配置提交到仓库，也不要
粘贴到 issue 或公开日志。

## 公网部署清单

- [ ] HTTPS/WSS 由持续维护的反向代理终止。
- [ ] 公网只开放 80/443；NekoNest 应用端口保持私有。
- [ ] 管理员密钥与注册令牌足够长、随机且互不相同。
- [ ] `NEKONEST_ALLOWED_ORIGINS` 只包含预期 HTTPS 来源。
- [ ] 仅当反代会覆盖客户端转发头时设置 `NEKONEST_TRUST_PROXY=1`。
- [ ] Server 使用非特权用户或加固后的非 root 容器运行。
- [ ] Server 数据目录与密钥文件只对该运行身份开放。
- [ ] 备份已加密、限制访问，并验证过恢复。
- [ ] Daemon 配置与身份文件只允许主机用户读取。
- [ ] debug 日志只临时启用，日志本身受访问控制。
- [ ] Web Push 密钥按其他服务凭据的标准生成和保存。

仓库提供的 Compose 使用非 root 镜像、只读根文件系统、丢弃 capabilities 和私有
数据挂载。自定义时应保留这些控制。

## 数据与内容

- 即使在 sealed 模式，Server 数据目录仍含敏感数据库和附件状态，必须整体备份。
- 上传文件和渲染 Markdown 都是不可信输入。PWA 会净化 Markdown，但运维者仍需
  及时更新浏览器与依赖。
- 智能体工具以 Daemon 用户权限在主机执行。需要更小文件边界时，使用专用系统
  账户或受限的智能体沙箱。
- 缺失或不受支持的控制必须保持禁用。不要绕过能力检查强行执行审批、转向、中断
  或文件访问。

## 凭据泄露后的处理

1. 移除公网访问或停止受影响组件。
2. 尽可能撤销受影响的手机或主机身份。
3. 按影响范围轮换管理员密钥或注册令牌，并重启 Server。
4. 重新注册、重新配对受影响设备。
5. 审查受访问控制的日志，只从确认可信的备份恢复。
