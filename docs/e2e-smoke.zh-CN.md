# 验收清单

新安装、升级，或变更依赖真实反代、Service Worker、主机 Daemon、原生智能体
存储或重连路径时，运行本清单。本地测试只是预检，不能替代这条真实流程。

## 修改线上实例前

- [ ] 记录已部署 Server、PWA 与 Daemon 版本或产物哈希。
- [ ] 备份 Server 数据目录、Server 密钥和主机 Daemon 状态。
- [ ] 保留旧 Server 镜像/二进制、PWA 与 Daemon 二进制作为回滚材料。
- [ ] 确认当前 `/health` 与主机在线状态正常。

## 核心路径

- [ ] 公网 `https://your-nest/health` 能通过反向代理访问。
- [ ] 错误管理员密钥被拒绝，正确密钥能完成初始化。
- [ ] `nekonest-daemon -doctor` 没有关键配置或网络错误。
- [ ] `install` 与 `start` 之后，`nekonest-daemon status` 显示主机服务已安装
      且进程锁被持有。
- [ ] 新配对码能连接预期主机，手机显示主机在线。
- [ ] 最近的原生主线程出现在**目录 → 智能体 → 线程**下。
- [ ] 打开线程后能载入原生历史，且没有重复回合。
- [ ] 短提示词能流式输出，并到达最终投递状态。
- [ ] 一张小图片或文本附件被交付，或者明确显示不支持原因。
- [ ] 若声明了中断，长回合能停止，主机进程不会残留。
- [ ] 停止 Daemon 后主机离线；重启后能重连并恢复线程视图。
- [ ] 关闭并重新打开 PWA 后能载入当前构建，不会陷入旧版本循环。

## 按能力验收

只测试 PWA 当前启用的控制：

- [ ] 声明审批、拒绝或转向时，能完成真实原生请求。
- [ ] Codex 规划模式提示会在 PWA 中产生真实结构化问题；回答后继续同一个原生回合。
- [ ] 队列在重连后保持顺序；原生执行前可取消排队项，不确定工作必须要求用户明确决策。
- [ ] 新建线程只能选择已发现项目，且原生创建确认后才进入该线程。
- [ ] 禁用的控制会解释不可用原因，而不是静默无效。

Codex 通常提供最完整的控制面。其他智能体可能只提供较小的兼容集合；应由运行
中的能力目录决定本清单，而不是静态表格。

## 传输检查

### Sealed 实例

- [ ] `/health` 报告 `sealed`，所有客户端都接受该模式。
- [ ] 配对完成，并确认预期的手机/主机身份。
- [ ] 唯一测试提示词、响应、路径、审批详情和附件名不会以明文出现在 Server 日志
      或数据库中。
- [ ] 重连不会让一次用户操作产生第二个原生回合。

### Open 实例

- [ ] `/health` 报告 `open`，首次使用的明文警告被明确接受。
- [ ] 运维者理解 VPS 可以读取应用内容。

不要在已有 open 数据目录上运行 sealed 测试，也不要在验收期间尝试改变实例已
保存的模式。

## 升级收口

- [ ] 多次重连/发现周期后，Server 与 Daemon 仍保持健康。
- [ ] PWA 与组件版本提示符合预期部署。
- [ ] 本次变更的用户流程在真实手机/主机路径上通过。
- [ ] 日志没有新的崩溃循环、重复鉴权失败或密钥材料。
- [ ] 验收完成前，回滚材料与备份位置都有记录。
